# Toreca Vault — 参考買取相場の更新手順（2026-11-17 JST）

## 目的と完成状態

新アプリの参考価格は**店舗の買取提示額**であり、購入原価・公式税込定価・希望販売価格・実際の買取成立額とは別の数値とする。店舗は当初「買取ミミ」「カードショップアリウム」「トレカショップKURO」。画像・商品名・状態・BOX/セット/カートン単位・元X投稿の日時を照合してから、現在有効な提示だけを買い取り評価に入れる。

**現在：無料の公開価格表を読むproviderを実装中。Cloud Run UI・Firestore staging canonicalへの配備は未完了のため、アプリに価格が反映されたとは扱わない。7日以内の表は取り込み、24時間を超えた提示は「旧価格」として表示するが、現在の資産評価には含めない。**

### 価格の証拠ゲート

1. 取得元はX APIではなく公開買取表 `https://torekakaku-navi.com/`。表の店舗名と対象**個別投稿URL**（`https://x.com/ACCOUNT/status/NUMERIC_ID`）を確認し、投稿IDから投稿日時を算出する。価格自体は公開表の転記値であり、アプリがX本文や画像をOCR/画像認識して照合する方式ではない。7日超の表、不一致、曖昧な情報は取り込まない。24時間を超えた表は現行価格にせず、確認済みの旧価格としてのみ保存する。
2. 商品は正式名称と公式パッケージ・ロゴ・カラー・キャラクターを照合。30th CELEBRATION拡張BOX、9種カードセット、デッキセットは**別商品**。状態（シュリンク有無、テープ、段ボール未開封）と数量単位（BOX/pack/case）を正確に指定。
3. **買取ミミ** ポケカ画像は上段赤＝シュリンク有、下段青＝シュリンク無。ONE PIECEは赤＝1BOX、青＝1ケース。**アリウム** ポケカ画像は上段水色＝シュリンク有、下段黒＝シュリンク無。**KURO** ポケカ画像は上段黒＝シュリンク有、下段白＝シュリンク無。凡例、テキスト、画像位置が矛盾する場合は`review`。
4. 価格表の掲載日・投稿日時・利用期限・限定数量を確認。ピックアップ限定が終了したら`superseded`/無効、最新の低い提示額を採用。最新の有効提示額が不明な場合は「未取得」、信頼できる過去の提示は「旧価格」と表示して**現在の評価合計へ含めない**。
5. 税込定価を根拠に買取価格を創作しない。過去の買取表の数字も現在の価格として使わない。

## 実装した構成

## 単品カードのチャット調査参考額

`owner-chat-researched-single-buyback-v1` の未検証参考額入力は、価格元コード `f/k/n/h/u` を使います：`f`=フルコンプ、`k`=カードラッシュ参照（二次掲載）、`n`=ナタデココ、`h`=晴れる屋2、`u`=ふるいち。価格日とカード加工は照合し、アプリ表示は「チャット調査・未検証」のままです。これは公式投稿の検証済み価格ではなく、本人が確認した参考値です。


- `cloud/src/buyback-quotes.js`: 公式元投稿のURL/日時/有効期限、shop、商品・状態・単位、verified状態の判定。店舗内では**最新の投稿のみ**を比較し、別店舗の現行提示額のうち最高額を取得。タイムスタンプ矛盾のある店舗は除外。
- `cloud/src/dashboard-view.js`: 参考買取評価額に原価代用なし。有効買取相場のある在庫の部分合計のみ。店舗別の金額と元投稿リンクを表示し、旧価格/未取得を明確に分離。
- `cloud/src/public-buyback-feed-provider.js`: X API認証なしで公開買取表を取得。7日以内のスナップショットを評価し、24時間以内は現行価格、24時間を超えたものは旧価格として記録する。許可店舗3店、個別X投稿URL、投稿IDからの日時、商品名、BOX/パック状態が確認できる場合のみ候補を返す。旧価格はUIに日付付きで表示するが資産評価には含めない。シングルカード等の非対応商品は既存の価格状態を変えない。
- `cloud/src/market-refresh-worker.js`: 定価/出典不明の値を拒否し、店舗ごとの保存枠を分離。公開表の取得は既存の15分Intakeスケジュールを再利用し、毎日13:30 JST以降の最初の15分Intake tickで同一日1回canonicalへ反映する。
- `cloud/src/verified-buyback-import.js`: 操作者が一次投稿の実内容を確認済みの非公開ローカルJSONを事前評価し、店舗別履歴を残しながらCAS更新・Firestore readback検証。事実が不一致なら適用停止。
- `cloud/scripts/import-verified-buyback.js`: ステージング限定の**preview**と明示承認後の**apply**。Google Cloudの認証済み環境が必要。実請求/バックアップを別に確認。GitHubへ個人保有商品の一覧やX画像・非公開JSONファイルをコミットしない。

### 非公開JSON入力の構造（架空テスト用・実相場として使用禁止）

```json
{
  "schemaVersion": 1,
  "mutationId": "verified-buyback:2026-11-14:manual-example-001",
  "quotes": [
    {
      "productKey": "example-box-a",
      "category": "BOX",
      "condition": "あり",
      "unit": "box",
      "price": 1000,
      "sourceStore": "買取ミミ",
      "postUrl": "https://x.com/mimi_kaitori/status/1234567890123456789",
      "postedAt": "2026-11-14T03:00:00+09:00",
      "validUntil": "2026-11-14",
      "status": "verified"
    }
  ]
}
```

上記はAPI契約だけを示すダミーデータ。**実在ポスト・確認済み商品・実額の証拠ではなく、絶対に実canonicalへ投入しない。** 実データで適用するには、本人の店舗投稿で価格/条件/有効性を照合したうえで、実際の`productKey`がFirestore inventory lotに正確に存在する必要がある。

### 認証済みCloud Shellでの安全な作業例

前提：`docs/CHAT_STAGING_RELEASE_RUNBOOK.md`に基づき既存GCPプロジェクト番号・バックアップの有効性・IAM・最新revを確認。cloud依存関係をインストールし、開発ブランチの作業コピーを取得する。

```bash
export GOOGLE_CLOUD_PROJECT=project-8ff0bbc4-675d-4596-a8a
export TV2_FIRESTORE_DOCUMENT=torecaVaultStaging/canonical

# 対象正本の既知revisionと、非公開の確認済み買取証拠JSONを指定
node cloud/scripts/import-verified-buyback.js preview /private/verified-quotes.json EXPECTED_REVISION

# 事前previewとバックアップ確認後だけ、明示承認して適用
TV2_VERIFIED_BUYBACK_IMPORT=YES TV2_BACKUP_VERIFIED=YES \
  node cloud/scripts/import-verified-buyback.js apply /private/verified-quotes.json EXPECTED_REVISION
```

`EXPECTED_REVISION`はCloud Shellで**現在のFirestore canonicalから読み取った整数**へ置き換える。プレビューは書込み0。反映は同一revisionのみ受理し、投稿・条件の同一性、重複、古い投稿の新規採用防止、異なる金額で同じ投稿URLを再使用する衝突防止を実施。成功時はrevision/readbackと追加/旧扱い件数だけ出力。商品の詳細や取引・認証情報は出力しない。

- 連続した投稿でも、店舗内は**より新しい投稿が先**。旧投稿は残すが`superseded`として現在価格に採用しない。
- 他店舗の証拠は上書きせず保持する。
- 既存の取引・在庫・抽選・購入原価は不変。
- `preview`/静的構造チェックだけでは**実在X投稿の確認はできない**。人が投稿と表を照合したことを別に記録すること。
- Firestore保存時のトランザクションCAS・保存後readback・バックアップを省略しない。実環境の権限不足であれば無理に公開化しない。
- 本番移行は別途承認。旧V2キューや未登録売却を価格調査のために再送しない。

## 2026-11-14 JST — 定期相場更新の複数店舗処理・古い値への巻き戻りを修正

- **修正前の問題**：`cloud/src/market-refresh-worker.js` の`lookupMany()`は同じ商品targetKeyを重複と扱い、ミミ・アリウム・KUROの複数の適切な買取提示額をまとめて返すと、その商品全体をあいまいとして無視していた。
- **修正後**：`(targetKey, sourceStore)`の組を識別し、**別店舗の値なら同一商品でも3店舗を独立受理**。同じ店舗から同じ対象へ2件返り、どちらが正しいか不明なときは**その店舗だけを無効**にし、他店舗の元投稿は採用可能。現在の出典・カテゴリ・シュリンク・単位・期限検証は継続。
- **時間順序**：すでに記録された新しい店舗投稿より前の日付のキャッシュや、同一URL/同時刻で異なる金額を返す入力は拒否。既存の新しい確認済みの提示は改変せず、レンダラー側の有効期限判定を優先する。新たな投稿は旧投稿をsupersededにして店舗ごとの履歴を保持。
- **別商品の混同防止**：`cloud/src/buyback-quotes.js`は`lotId`の一致だけで商品名・カテゴリ・販売単位の矛盾を許可しない。BOXにカード単体の単位が付いた提示は採用しない。
- **検証**：`cloud/test/market-refresh-worker.test.js` と `cloud/test/buyback-quotes.test.js` に3店舗同時取得、同店舗矛盾/他店のみ採用、値下げ後の旧高値不採用、古いキャッシュ入力の拒否、lotIdのカテゴリ衝突試験を追加。GitHub Actions [#43571906100](https://github.com/manato-maker/toreca-vault/actions/runs/43571906100)のtest/Firestore Emulatorは両方success。
- **実運用**：これはGitHub開発ブランチ上の実装修正であり、Cloud Run/Firestoreの実サービスへは未デプロイ。11/14本人一次X投稿の金額・単位と期限を検証できていないため、価格の実登録は今回も行っていない。認証済みFirebase/Google Cloudの接続と、実在庫に一致する元投稿を確認した後にstagingからE2E検証する。


## 2026-11-14 JST — 買取価格の出典必須化と販売中止後の旧価格復活防止

- **追加したコードの検査**：`cloud/src/buyback-quotes.js` が`lotId`一致だけでは買取価格を結び付けないよう改修。**商品ID/名前・販売単位・カテゴリ・シュリンク状態は必ずそれぞれ一致**し、出典が「公式定価」「販売価格」「MSRP」であれば、店舗名や元投稿の形式だけ正しくても参考買取額として扱わない。
- **時系列のバグ修正**：買取ミミ等の同一店に新しい「買取終了/提示期限終了」投稿があっても、旧提示がまだ日付上有効であれば高額買取額として再登場してしまう可能性を解消。店舗ごとの元投稿を**期限切れ/買取終了を含め日時の新しい順**に比較し、最新投稿が有効でない場合は古い高値を現在価格に採用しない。矛盾した同時刻の投稿はshopだけreviewにし、他店の価格は守る。JSTとUTCの文字列表記差は絶対時刻で比較。
- **過去価格の要件**：出典URLと実際の投稿日時（タイムゾーン付き）の両方が証明できないものは「過去の確認済み価格」にも表示しない。月日だけで「元の投稿日時」としない。
- **テスト**：`cloud/test/buyback-quotes.test.js` にIDだけ一致で商品不明・単位不明、店舗があってもsourceがMSRP、終了投稿後の旧高値再登場、タイムゾーンの比較、日付だけの価格を拒否する回帰ケースを追加。`test` / `firestore-emulator` 両ジョブが成功したActions [#43572888397](https://github.com/manato-maker/toreca-vault/actions/runs/43572888397) を確認した。
- **外部価格調査**：買取ミミ、アリウム、KUROの公式Xアカウントは公開検索で確認できたが、**2026-11-14の全商品について本人の最新個別ポスト・画像・税込価格・BOX条件・数量制限を確証できる一覧**は得られていない。過去・不確かな転記金額はFirestoreへ投入しない。
- **反映範囲**：コードと自動テスト、手順書のみ。Cloud Runステージングの認証付き画面はこの接続から閲覧できず、FirestoreのmarketQuotes更新・アプリデプロイは未実行。実際の参考買取金額は変更されていない。今後、元投稿の確証、Google Cloud認証、バックアップ、dry-run、CAS反映後のreadbackが必要。


## 2026-11-19 JST — 相場更新時刻の変更

- 相場更新の起動条件を22:00 JST以降から、13:30 JST以降へ変更。既存の15分Intake tickを使い、専用Scheduler jobは追加しない。
- 13:30のtickで実行し、Schedulerの遅延時は13:30以降の次のtickで実行する。同じ日付のmutation keyにより、日次1回の更新となる。
- 13:30以降の最初の15分tickで実行する。今回の旧価格表示対応は`stale-display-v1`付きの別idempotency keyを使うため、すでに実行済みの日でもstagingへ修正版を反映した後の次のtickで一度だけ更新できる。翌日以降も同じdaily keyで重複を防ぐ。手動Firestore書込みや手動Scheduler実行は不要。
- 24時間を超えた提示は現行価格として使わず、7日以内に限って出典・投稿日時付きの「旧価格」として保存・表示する。旧価格は参考評価合計へ含めない。
